# Сигурно чат приложение с End-to-End криптиране (E2EE)

Конзолно чат приложение написано на C, което осигурява сигурна комуникация между двама потребители чрез хибридна криптосистема (RSA + AES-256-GCM).

---

## Компилиране и стартиране

### Изисквания
- GCC компилатор
- OpenSSL библиотека (`libssl-dev` / `openssl-devel`)

### Компилиране
```bash
make
```

### Стартиране

**1. Стартирайте сървъра** в един терминал:
```bash
./main
```

**2. Стартирайте първия клиент** в друг терминал:
```bash
./client
# Отговорете 'y' (този клиент започва обмена на ключа)
```

**3. Стартирайте втория клиент** в трети терминал:
```bash
./client
# Отговорете 'n'
```

След като и двата клиента се свържат, можете да си пишете съобщения.

---

## Структура на пакетите

Комуникацията между клиентите преминава през сървъра-релей, който не може да прочете съдържанието.

### Фаза 1 — Обмен на RSA публични ключове
```
[ 4 байта: дължина ] [ N байта: RSA публичен ключ в PEM формат ]
```
Всеки клиент изпраща своя публичен ключ и получава този на другия.

### Фаза 2 — Обмен на AES сесиен ключ
Клиент A (започващият):
```
[ 4 байта: дължина ] [ 256 байта: AES ключ, криптиран с RSA-OAEP ]
```
Клиент B декриптира с частния си ключ и двамата имат един и същи AES-256 ключ.

### Фаза 3 — Криптирани съобщения
```
[ 4 байта: дължина на ciphertext ]
[ 12 байта: IV (Initialization Vector) ]
[ 16 байта: GCM Authentication Tag ]
[ N байта: криптиран текст ]
```
Всяко съобщение използва уникален произволен IV, генериран с `RAND_bytes()`.

## Описание на трудностите

**1. Грешка при RSA декриптиране (`bad length`)**  
При извикване на `EVP_PKEY_decrypt()` параметърът `outlen` трябва да сочи към буфер с размер поне колкото RSA ключа (256 байта за RSA-2048), а не колкото очаквания plaintext (32 байта). Грешката се проявяваше само при клиента, който декриптира (отговарящият с `n`), и беше поправена чрез задаване на `outlen = rsa_size`.

**2. Синхронизация на handshake-а**  
Двата клиента трябва да разменят ключове в точна последователност. Въведен е `READY` пакет, с който клиент B сигнализира готовност преди клиент A да изпрати криптирания сесиен ключ.

**3. Едновременно четене от мрежа и клавиатура**  
Използван е `select()` за мониторинг едновременно на сокета и `stdin`, без да се блокира нито едното.
